## 一、数据处理

### 1.1 数据集

| | NEU-DET | GC10-DET |
|---|---|---|
| 材质 | 热轧钢带 | 冷轧钢板 |
| 原始分辨率 | 200 × 200 | 2048 × 1000 |
| 类别数 | 6 | 10 |
| 图像总数 | 1800 | 2280 |
| 标注格式 | VOC XML | VOC XML |

NEU-DET 每类恰好 300 张，类别完全平衡；GC10-DET 长尾明显（`crease` 训练集仅 46 个框，`silk_spot` 有 639 个）。

### 1.2 三分划分

两个数据集使用**完全相同**的划分协议，否则无法放进同一张表：

- 比例 70 / 15 / 15
- 按每张图的**主类别**（框数最多的类）分层
- 随机种子 0
- 符号链接而非复制

| | train | val | test |
|---|---|---|---|
| **NEU-DET** | 1260 图 / 2907 框 | 270 / 641 | 270 / 641 |
| **GC10-DET** | 1596 图 / 2474 框 | 344 / 548 | 340 / 520 |

每图平均框数：NEU-DET 2.31，GC10-DET 1.55。

实现：[`make_split.py`](../make_split.py)、[`make_gc10.py`](../make_gc10.py)。

**为什么要独立测试集。** 文献中 NEU-DET 的通行做法是 train/val 两分，报告验证集上最优 epoch 的分数。我们实测同一批权重从 val 到 test 会系统性下降（见项目总结 §4.2），量级超过大多数论文声称的改进幅度。三分划分是本项目所有结论的前提。

### 1.3 GC10-DET 的两个坑

**标注拼写不一致。** 类别 10 在发布的 XML 里有三种写法：

```python
ALIASES = {"10_yaozhed": "10_yaozhe", "d": "10_yaozhe", "10_yaozh": "10_yaozhe"}
```

### 1.4 数据增强

| 变换 | 概率 / 幅度 |
|---|---|
| 水平翻转 | 0.5 |
| 垂直翻转 | 0.3 |
| 90° 旋转 | 0.3 |
| 亮度扰动 | 0.3 |
| 仿射缩放 | 0.5 |
| 仿射平移 | 0.1 |
| **Mosaic** | **0.0（禁用）** |

**Mosaic 被禁用是实测结论，不是默认设置。** 开启 mosaic=1.0 的对照实验（`x_mosaic_fix`）得到 mAP50 = 0.5536，远低于关闭时的 0.756。NEU-DET 原图仅 200×200，缺陷常占据画面的很大比例（`pitted_surface` 框的中位边长为 146 px，即原图的 73%），四图拼接后单个缺陷被压缩到无法辨认的尺度。

垂直翻转和 90° 旋转对自然图像检测通常有害，但钢材表面缺陷没有重力方向先验，因此可用。

### 1.5 类别的尺度分布

NEU-DET 训练集，框的 √(w·h)，以原图 200 px 为尺度：

| 类别 | 框数 | 中位边长 | 均值 | 最大 |
|---|---|---|---|---|
| crazing | 477 | 91.5 | 92.9 | 151.4 |
| inclusion | 700 | 39.8 | 47.3 | 141.0 |
| patches | 613 | 60.6 | 67.3 | 162.5 |
| **pitted_surface** | 307 | **146.5** | 144.1 | **199.0** |
| rolled-in_scale | 440 | 71.4 | 73.8 | 153.5 |
| scratches | 370 | 56.1 | 58.1 | 135.3 |

尺度跨度接近 4 倍。`pitted_surface` 的中位框边长是原图的 73%，最大接近整图——这类目标在 640 px 输入下对应 469 px 的框，只有 stride 32 的 P5 层能表示。该分布直接决定了后文频域分支只接在 P4/P5 而不接 P2/P3。

## 二、检测框架

整体是 YOLOv8 风格的单阶段无锚检测器，主干可替换。所有对比实验共享 neck、head、损失和训练循环，**只更换主干**，以保证消融的因果归属。

```
输入 640×640
   │
   ├── 主干（可替换：cnn / freqdual / hiera / freqhiera / ultra）
   │      └── 输出 4 个层级 P2/P3/P4/P5，stride 4/8/16/32
   │
   ├── PANet neck（width 192, depth 1）
   │
   └── 解耦检测头（reg_max=16，DFL）
          ├── 分类分支
          └── 回归分支（distribution focal loss）
```

### 2.1 主干：CSPBackbone

[`model/backbone_cnn.py`](../model/backbone_cnn.py)。CSPDarknet 结构，width 0.5 / depth 0.34。

| 我们的模块 | 通道 | 对应 ultralytics |
|---|---|---|
| `stem` | 3 → 32, s2 | `model.0` |
| `stage1` | 32 → 64, C2f×1 | `model.1-2` |
| `stage2` | 64 → 128, C2f×2 | `model.3-4` |
| `stage3` | 128 → 256, C2f×2 | `model.5-6` |
| `stage4` | 256 → 512, C2f×1 | `model.7-8` |
| （无 SPPF） | | `model.9` |

逐张量核对确认与 **yolov8s** 主干等价（125 个张量全部形状匹配，仅缺我们的 neck 不消费的 SPPF）。注意是 v8s 而非 v8n——我们的 width 0.5 是 v8n 的 0.25 的两倍。

因此 `load_coco_checkpoint()` 可以把 COCO 预训练权重逐层搬入。该功能已实现并验证，但实验证明它在本数据集上无效（见项目总结 §5.3）。

### 2.2 Neck 与 Head

- **PANet**：自顶向下 + 自底向上双路径特征金字塔，宽度 192
- **解耦头**：分类与回归分支分离，`reg_max = 16`，回归用 DFL（Distribution Focal Loss）建模边界的离散分布而非直接回归坐标
- **无 objectness 分支**（`--no-obj`）：TAL 分配已提供正负样本的软标签，额外的 objectness 分支在小数据集上是冗余参数

### 2.3 损失与标签分配

[`model/loss.py`](../model/loss.py)。TAL（Task-Aligned Assigner）+ DFL + CIoU。

**关键实现细节：分配器必须在 fp32 中运行。**

```python
# Assignment happens in image pixels, the box/dfl losses in grid units.
# The assigner MUST run in fp32.  Under autocast the predicted boxes
# arrive as fp16, and CIoU squares the enclosing-box diagonal: at 640px
# that is 640^2 = 409600, well past the fp16 ceiling of 65504.
t_labels, t_bboxes, t_scores, fg = self.assigner(
    pred_scores.float(), (pred_bboxes.detach() * strides).float(),
    anchors.float(), gt_labels.float(), gt_bboxes.float(), mask_gt, ...)
```

在混合精度下，CIoU 计算外接框对角线的平方。当框的边长超过 181 px 时该值溢出 fp16 上限 65504，返回 inf，导致**所有大框都得不到正样本**。这个 bug 使 `pitted_surface` 这类大目标的 P5 层正样本数长期为 0（日志中的 `pos/32: 0.0`），修复后整体 mAP50 提升 **+0.146**。

我们在训练日志中加入了每层级的正样本计数（`pos/8`、`pos/16`、`pos/32`），正是这个指标暴露了问题。

### 2.4 评估

[`model/metrics.py`](../model/metrics.py)。COCO 101 点插值 AP，NMS IoU 阈值 0.45。

**TP 分配必须按置信度而非 IoU。** 早期实现在两次 `np.unique` 之间插入了按 IoU 的排序，导致每个 GT 保留的是 IoU 最高的检测而非置信度最高的，AP 被系统性低估约一半：

```python
matches = matches[matches[:, 2].argsort()[::-1]]
# After this de-duplication the rows are ordered by DETECTION index,
# and detections arrive sorted by confidence -- so de-duplicating by
# ground truth next keeps the most confident detection for each box.
matches = matches[np.unique(matches[:, 1], return_index=True)[1]]
matches = matches[np.unique(matches[:, 0], return_index=True)[1]]
```

修复后 mAP50 提升 **+0.06**。

## 三、频域双域主干（FreqDual）

[`model_newage/freqdual.py`](../model_newage/freqdual.py)。这是本项目提出的结构。

### 3.1 动机

表面缺陷的判别信息很大程度上是**纹理性**的：`crazing` 是密集细裂纹的统计特征，`rolled-in_scale` 是周期性压入痕迹。这类信号在频域中的表示远比在像素域中紧凑——但标准 CNN 只能通过堆叠卷积隐式地逼近频率选择性。

我们的做法是显式地并行计算一条频域通路，与空间通路在深层融合。

```
输入
 ├──────────────► CSPBackbone ─────► P2  P3  P4  P5
 │                                        │   │
 └──► SpectralStem                        │   │
        分块 rfft2                         │   │
        径向 × 方向频带池化                  │   │
        conv stack ──► F_p, F_2p ──融合───►┘   │
                                    (类别门控)  │
                                               ▼
                                         PANet + Head
```

### 3.2 SpectralStem

将图像切成 16×16 的不重叠块，每块做 `rfft2`，然后按**径向 × 方向**的频带划分池化：

- 径向带 `n_radial = 8`（低频到高频）
- 方向带 `n_orient = 4`
- 共 32 个频带描述子，取 `log1p(|Z|)` 后与预计算的带掩码矩阵相乘

输出的空间分辨率等于 patch 大小，即 stride 16 —— 正好落在 P4，再经一次 stride-2 卷积到达 P5。

**为什么只接 P4/P5**：由 §1.5 的尺度统计，弥散类别的框在 216–489 px 之间，远超 stride 8 能表示的范围。而 P2/P3 承载的是 `scratches`、`inclusion` 这些清晰的小目标——历次实验中，任何扩大感受野的改动都会损害它们。因此频域通路刻意不触碰浅层。

可选项（均已消融，见项目总结 §5）：
- `hann`：Hann 窗抑制块边缘的阶跃，避免高频带测到的是窗口效应而非纹理
- `phase`：每个频带相位的圆均值（cos/sin），携带幅度无法表达的位置信息
- `log_radial`：径向带按对数而非线性划分
- `use_fft=False`：消融对照，保持完全相同的参数量与数据通路，仅去掉变换

### 3.3 ClassGate

```python
class ClassGate(nn.Module):
    """The per-class affinity is learned rather than hand-set."""
```

从 P5 特征预测每张图的类别分布，再经一个可学习的**每类亲和度**向量映射为一个标量门控值，用于调节频域通路的融合强度。直觉是：`crazing` 这类纹理主导的图应放大频域分支，`scratches` 这类形状主导的图应压制它。

类别预测同时作为辅助分类损失（`aux_cls_weight = 0.2`）监督，标签是图中出现的所有类别的多标签向量。

**实现陷阱**：`forward` 中缓存的 logits 若在 eval 路径保留计算图，`copy.deepcopy(model)` 会失败（EMA 评估需要深拷贝）。必须消费后清空：

```python
self.logits = logits if self.training else None
```

### 3.4 CrossDomainFusion（可选）

余弦注意力融合两条通路。第一版直接点乘 fp16 的卷积特征，logits 溢出后 softmax 变成 NaN，训练中途整体崩到 mAP 0.000：

```python
# Bounded logits, fp32 softmax.  The first version dotted raw conv
# features in fp16 under autocast; ... softmax turns NaN, and the model
# collapses to mAP 0.000 mid-run
q = F.normalize(self.q(spatial).flatten(2).transpose(1, 2), dim=-1)
k = F.normalize(self.k(spec).flatten(2), dim=1)
logits = (q.float() @ k.float()) * self.logit_scale.exp().clamp(max=50)
```

修复后训练稳定，但**性能无提升**（Δ = −0.0004，t = −0.09）。

### 3.5 MPSBand（张量网络，已归档）

频带描述子本质上是一个 (径向 × 方向) 的二阶张量，而 `SpectralStem` 将其展平成 32 个无序通道送入 3×3 卷积，丢弃了「频带 r 与 r+1 是同一纹理的相邻尺度」这一结构。

`MPSBand` 把径向轴视为矩阵乘积态（MPS）的格点链：格点 r 携带方向向量（外加一个常数项，使该格点可以退出乘积），每个格点贡献一个 χ×χ 矩阵，输出是所有矩阵的有序乘积。这使映射成为输入的 `n_radial` 次多项式，参数量仅 O(R·O·χ²) = 10.8k——一种线性通道混合在任何宽度下都无法表达的**跨尺度乘性交互**。它是作用在频带寄存器上的量子线路的经典（张量网络）极限：无采样，无贫瘠高原，完全可微。

**数值稳定性**：每个格点收缩后必须对运行向量归一化，否则八个矩阵连乘会在数百步内溢出或下溢。收缩强制 fp32。

**结果：零结果**（7×2 种子，Δ = −0.0004，crazing t = 2.00 < 阈值）。详见项目总结 §5.2。代码保留在仓库中作为消融记录。

### 3.6 其他模块

| 模块 | 作用 | 结论 |
|---|---|---|
| `SpatialGate` | 在类别门控之上叠加逐像素调制 | 无提升 |
| `BandRouter` | 按类别 logits 重加权各频带 | 零和再分配，无净增益 |
| `AuxSegHead` | 挂在 P3 的辅助密集分割头 | 未采用（`aux_seg_weight = 0`） |

## 四、对照主干

为隔离「架构问题」与「训练问题」，实现了三个对照主干，全部走同一套 neck/head/loss/训练循环：

| `--backbone` | 说明 |
|---|---|
| `cnn` | 纯 CSPBackbone，消融基线 |
| `hiera` | SAM2 的 Hiera 层次化 ViT，冻结主干 + 每阶段适配器 |
| `freqhiera` | 频域通路 + Hiera 主干 |
| `ultra` | ultralytics 的架构跑在我们的训练循环里 |

`ultra` 的作用是诊断性的：如果它在我们的循环里表现正常而我们的架构不正常，问题在架构；如果两者都不正常，问题在训练循环或数据。这是把 mAP50 从 0.3585 修到 0.73 的关键工具。

外部参照通过 [`ref_yolov8.py`](../ref_yolov8.py) 运行原版 ultralytics（YOLOv8n / YOLOv8s / RT-DETR-l），使用相同的三分划分。

## 六、可复现性

```bash
# 环境
source ~/miniconda3/bin/activate && conda activate defect

# 数据划分
python make_split.py            # NEU-DET
python make_gc10.py             # GC10-DET

# 训练（主实验）
python -m model.train --backbone freqdual --data neu-det-3way \
    --train-split train --val-split val --imgsz 640 --epochs 150 \
    --seed 0 --name f3_freq_s0

# 外部参照
python ref_yolov8.py --model yolov8n.pt --data neu-det-3way/neu-det-3way.yaml \
    --epochs 150 --imgsz 640 --seed 0 --name f3_v8n_s0

# HPC 批量提交
./submit.sh <run-name> <train.py 参数...>
./run_overnight.sh              # 补齐所有缺失的实验
./report_all.sh                 # 分组均值 + Welch t 检验
```

诊断工具（`model/*check.py`、`model/*probe.py`）保留在仓库中，它们是基线恢复过程的记录：`crosscheck`（与参照实现逐模块比对）、`losscheck`、`predcheck`、`metriccheck`、`nmssweep`（NMS 阈值扫描）、`levelprobe`（逐层级正样本诊断）。
